## LA SEMANTICA DE `conflicto`, DECIDIDA CON EL USUARIO

`conflicto` significa **el `UNIQUE` rechazo mi escritura**. Con las **dos**
condiciones, porque con una sola la senal se muere:

```
solo `not insertado`           -> MEDIDO: el estado 2 (reingerir lo MISMO)
                                  daba conflicto=True y B26 dejaba de ser
                                  idempotente
solo `previo_valor != intento` -> aviso FALSO con cada fichero de >1 import
```

Los siete estados, MEDIDOS, con `conflictos` y no con filas:

```
vacio                        -> False
lo MISMO (idempotencia)      -> False
otro objeto, MISMA fuente    -> False   <- lo que 0008 permitio
otra fuente, mismo valor     -> False
otra fuente, OTRO valor      -> False
revision POSTERIOR, otro val -> False   <- supersesion, no conflicto
colision de CLAVE PRIMARIA   -> True    <- lo que SI se pierde
```

**Y LA SENAL NO ESTA MUERTA.** Con `0008`, el `UNIQUE` de la tupla natural
rechaza solo cuando coincide la tupla COMPLETA, que incluye el objeto, luego
implica que el valor era el mismo y la comparacion anula el aviso. La unica
colision que significa «no se escribio lo que dijiste» es la clave primaria.
Por eso el `previo is None` dejo de ser un retorno temprano: MEDIDO, sin eso
esa colision pasaba sin avisar.

**CONSECUENCIA DECLARADA, NO TAPADA.** Por la via de `normalizar` un conflicto
es ahora **inalcanzable**, y el motivo es estructural: `normalizar` deriva el
`claim_id` de (sujeto, predicado, objeto, fuente, revision), luego dos
claims distintos tienen `claim_id` distinto y el `UNIQUE` no puede rechazar.
Que `conflictos` salga vacio **no es que el aviso se haya tragado**: es que no
hay nada que avisar. Quien aun lo necesita es quien construye `Claim` A MANO
— la promocion.
