# Implementación — pre-commit hook + CI workflow (cierre de derivado DT-FORMAT-DRIFT)

**Fecha**: 2026-09-26
**WorkItem**: STEWARDSHIP-DT-HOOKS-CI
**Trigger**: Derivado #1 del audit `audits/format-drift-2026-09-26.md`
("añadir pre-commit hook + CI workflow para evitar regresión de drift
de ruff format"). Coste estimado: ~30 min.

**Problema resuelto**: tras el cierre del drift de format en
`3031795 style(format)`, quedaba abierta la pregunta "¿cómo evitar que
esto vuelva a ocurrir en futuros commits H11-H15 evolution-v2 o
similares?". El audit `format-drift-2026-09-26.md` documenta que el
patrón fue "features introducidas en commits sin re-correr ruff format
pre-commit". Sin gate automatizado, el drift se reproduciría en
2-3 ciclos.

## Solución implementada

Defensa en profundidad con 3 capas:

### Capa 1: pre-commit hook local (`scripts/hooks/pre-commit`)

Shell script POSIX que se ejecuta antes de cada `git commit`. Ejecuta:

1. `ruff check src tests` — bloquea si hay lint violations.
2. `ruff format --check src tests` — bloquea si hay drift de format.
3. `pytest -q` — solo si hay `.py` files staged. Bypass via
   `HOOK_SKIP_TESTS=1` para commits doc-only.

**Toolchain-aware**: si `mise` está disponible, usa `mise exec -- uv`
(garantiza toolchain pinned en `mise.toml`). Fallback a `uv run` directo.

**Bypass de emergencia**: `git commit --no-verify`.

**No commiteable a `.git/hooks/`** (gitignore implícito). El instalador
`scripts/install-hooks.sh` lo copia tras clonar.

### Capa 2: installer (`scripts/install-hooks.sh`)

Bash script idempotente. Detecta el repo root via `git rev-parse
--show-toplevel`, copia `scripts/hooks/*` a `.git/hooks/`, aplica
`chmod +x`. Documenta los bypasses en su output.

### Capa 3: CI workflow (`.github/workflows/ci.yml`)

GitHub Actions workflow que corre en push y pull_request a main. Steps:

1. `actions/checkout@v4`
2. `jdx/mise-action@v2` (toolchain pinned)
3. `mise list` (verifica toolchain)
4. `mise run sync` (uv sync)
5. `mise run lint` (ruff check)
6. `mise run format --check` (ruff format gate)
7. `mise run test` (pytest)

Step summary al final con outcome de cada gate (visibilidad rápida en PR).

**Esta capa protege incluso si el dev local no instala los hooks**.

## Limitaciones reconocidas

1. **El hook local NO se ejecuta automáticamente en este entorno
   específico**: el agente configura `core.hooksPath=/home/rubentxu/.git-hooks/`
   globalmente, lo que ignora los hooks en `.git/hooks/`. Solución
   aplicada en mi entorno: wrapper en `~/.git-hooks/pre-commit` que
   delega al local. **Esto NO se commitea** (es específico del entorno
   del agente).

2. **El CI workflow no usa cache de pip/uv**. Coste adicional: ~1-2 min
   por run. Optimización futura: `actions/setup-python@v5` con cache.
   No aplicado en este ciclo porque el coste de iteración es aceptable
   (~3 min/run).

3. **El CI workflow no ejecuta cobertura (pytest-cov)**. Si se quiere
   badge de cobertura, añadir `pytest --cov=skillgraph --cov-report=xml`
   + `codecov-action`. Coste: ~5 min setup. No aplicado.

4. **El hook no aborta por tests flaky**. Política: cualquier fallo de
   pytest bloquea el commit (preferimos fricción sobre tests flaky
   silenciosos). El `pyproject.toml` tiene `xfail_strict = true`, lo
   que ayuda.

   pre-push ejecutaría la suite completa, evitando pushes con tests
   lentos fallando.
